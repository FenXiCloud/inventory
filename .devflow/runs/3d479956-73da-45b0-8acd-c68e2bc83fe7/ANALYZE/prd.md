## 1. 项目目标

建设一套面向中小企业的**免费、开源、易用的进销存 ERP 系统**，以 SaaS 多租户模式交付，覆盖企业采购、销售、库存、资金四大核心业务域，实现进销存一体化管理。

具体目标：

- **G1 业务一体化**：打通「采购订单 → 采购入库 → 采购退货」与「销售订单 → 销售出库 → 销售退货」的完整单据链路，单据审核后自动联动库存与往来资金。
- **G2 库存精细化**：支持多仓库、调拨、盘点、其他出入库、成本调整，提供移动加权平均 / 先进先出两种成本核算方法及库存批次成本追溯。
- **G3 资金闭环**：收款、付款、其他收支、账户转账、核销单与客户/供应商往来对账，形成资金流闭环。
- **G4 多租户 SaaS 化**：平台管理端（admin）统一管理商户、账套与模块授权；商户端（merchant）独立运营，支持多账套、多员工、角色化权限。
- **G5 开箱即用**：初始账号开箱可用（13944878765 / 878765），内置打印模板、编码规则、期初建账（库存/应收/应付期初）能力。
- **G6 可扩展**：核心开源（Apache-2.0），预留打印模板、财务关联（凭证）、电子发票、移动端等扩展方向。

### 1.1 成功标准（验收口径）

1. 四大业务域（采购/销售/库存/资金）单据流转闭环，审核后库存与资金数据一致；
2. 成本核算结果可追溯（按成本批次/流水可查）；
3. 平台端可管理商户并控制商户可用模块；
4. 已知问题清单（第 8 章）全部有明确状态与处理结论；
5. 文档通过干系人评审并确认（见第 9 章）。

## 2. 系统范围与架构概述

### 2.1 系统组成

| 组成 | 说明 | 现状 |
|------|------|------|
| `admin` 管理端（admin-front/admin-server） | SaaS 平台管理：商户管理、账套、模块授权、菜单、平台用户 | 已有（Vue + TDesign + Spring Boot） |
| `merchant` 商户端（merchant-front/merchant-server） | 商户日常业务：基础资料、采购、销售、库存、资金、设置 | 已有（Vue + TDesign + Spring Boot） |
| `kernel` 核心模块 | 共享实体/枚举/服务，业务规则核心 | 已有（Java 17 + Spring Boot + JPA） |
| `app` 移动端 | uni-app 移动应用 | **极早期**：仅登录页与首页框架 |

### 2.2 关键业务实体（摘要）

- 基础资料：`Product`（商品）、`ProductCategory`、`Unit`（单位）、`Customer` / `Supplier`（客户/供应商）及分类/等级、`Warehouse`（仓库）、`Account`（资金账户）/`AccountType`、`PaymentMethod`（付款方式）、`PricingPolicy`/`PriceRecord`（价格策略与记录）。
- 采购：`PurchaseOrder`（采购订单）、`PurchaseInbound`（采购入库，关联 `orderId`）、`PurchaseReturn`（采购退货，经 `PurchaseInboundReturnConnection` 关联入库单）。
- 销售：`SalesOrder`（销售订单）、`SalesOutbound`（销售出库，关联 `orderId`）、`SalesReturn`（销售退货）。
- 库存：`Inventory`、`InventoryItem`（流水）、`InventoryCostBatch`/`InventoryCostConsume`（成本批次）、`StockTake`（盘点）、`InventoryTransfer`（调拨）、`CostAdjustment`（成本调整）、`OtherInbound`/`OtherOutbound`。
- 资金：`OrderReceipt`（收款单）、`OrderPayment`（付款单）、`OtherReceipt`/`OtherExpense`（其他收支）、`AccountTransfer`（账户转账）、`Verification`（核销单）、`AccountFlow`/`CustomerFlow`/`SupplierFlow`（流水与往来）。
- 设置与平台：`Merchant`（商户）、`AccountBook`（账套）、`Admin`（员工）、`Role`（角色）、`Menu`/`MenuRole`/`MerchantMenu`（菜单与授权）、`CodeRule`（编码规则）、`PrintTemplate`（打印模板）、`SystemConfig`、`SystemLog`、`DataBackup`（备份）、`Checkout`（结账）、`FinanceRel`/`FinanceVoucher`（财务关联与凭证）。

### 2.3 关键业务规则（现状事实）

- 单据状态机：`已保存 → 未审核 → 已审核`（`OrderStatus` 枚举）；审核后单据生效并联动库存/资金。
- 库存操作类型（`OperationType`）：期初余额、采购入库、销售退货、其他入库、盘盈入库、调拨入库、采购退货、销售出库、其他出库、调拨出库、盘亏出库、成本调整、期初库存。
- 成本核算：`CostingMethod` = 移动加权平均 / 先进先出（账套参数 `costAccounting`：1=移动加权，2=先进先出）。
- 负库存控制：商户级开关 `Merchant.stockField`（允许负库存）。
- 多账套：一个商户可建多个账套（`AccountBook`），业务数据按账套隔离。
- 编码规则：`CodeRule` + `CodeSeed`，支持按天/月/年/不重置（`ResetCycle`）。

## 4. 核心业务流程

### 4.1 采购流程

```
采购订单(PurchaseOrder) ──审核──> 采购入库(PurchaseInbound, 关联orderId) ──> 库存增加 + 应付增加
                                        │
                                        └──> 采购退货(PurchaseReturn, 经 PurchaseInboundReturnConnection 关联入库单)
                                                └──> 库存减少 + 应付冲减
```

1. 采购员录入采购订单（商品、数量、单价、供应商），保存后提交审核；
2. 货到后按订单生成采购入库单，审核后库存增加、生成供应商应付（`SupplierFlow`）；
3. 发生退货时，基于入库单生成采购退货单，审核后库存减少、冲减应付；
4. 付款环节：付款单（`OrderPayment`）→ 核销单（`Verification`）冲销应付；支持期初应付建账（`SupplierInitial`）。

### 4.2 销售流程

```
销售订单(SalesOrder) ──审核──> 销售出库(SalesOutbound, 关联orderId) ──> 库存减少 + 应收增加
                                        │
                                        └──> 销售退货(SalesReturn) ──> 库存增加 + 应收冲减
```

1. 销售员录入销售订单（支持「以销订购」联动补货，见现状提交记录），保存后提交审核；
2. 出库后库存减少、生成客户应收（`CustomerFlow`）；
3. 退货基于出库单生成销售退货单，库存回补、冲减应收；
4. 收款环节：收款单（`OrderReceipt`）→ 核销单冲销应收；支持期初应收建账（`CustomerInitial`）。

### 4.3 库存流程

```
入库类：采购入库 / 销售退货 / 其他入库 / 盘盈入库 / 调拨入库 / 期初库存
出库类：销售出库 / 采购退货 / 其他出库 / 盘亏出库 / 调拨出库
调整类：成本调整(入库调整/出库调整) / 盘点(盘盈=其他入库, 盘亏=其他出库)
核算类：成本批次(InventoryCostBatch/Consume) —— 移动加权平均 / 先进先出
```

1. 一切库存变动记录于 `InventoryItem` 流水，按 `OperationType` 区分业务来源；
2. 调拨（`InventoryTransfer`）实现仓库间货权转移（调拨出库 + 调拨入库成对发生）；
3. 盘点（`StockTake`）支持按仓库盘点，差异以盘盈/盘亏出、入库单处理；
4. 成本调整单（`CostAdjustment`）修正库存成本，联动成本批次；
5. 库存查询提供现存量、汇总、明细、成本批次多视角报表；商户可开启/关闭负库存。

### 4.4 资金流程

```
收款：客户应收 ← 收款单(OrderReceipt) ← 核销单(Verification)  ← 账户(Account) 资金增加
付款：供应商应付 ← 付款单(OrderPayment) ← 核销单(Verification) ← 账户资金减少
其他：其他收入(OtherReceipt) / 其他支出(OtherExpense) / 账户转账(AccountTransfer)
对账：客户对账单 / 供应商对账单 / 账户流水(AccountFlow) / 收支类别报表
```

1. 收款/付款单记录资金收付，可核销到具体单据（`OrderReceiptCollection`/`OrderPaymentCollection`/`VerificationCollection`）；
2. 支持整单核销与部分核销，未核销余额可追踪（`SourceByVerification` 等视图）；
3. 收支类别可映射财务科目（`FinanceItemMap`），为财务凭证生成（`FinanceVoucher`）与结账（`Checkout`）提供基础。

## 6. 非功能需求

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-01 | 性能 | 常规单据（<100 行明细）操作响应 ≤ 2s；库存流水查询在千万级流水下分页响应 ≤ 3s |
| NFR-02 | 数据一致性 | 单据审核/库存变动/资金变动必须事务一致；成本核算结果可追溯；不允许因并发产生负库存（未开启负库存时） |
| NFR-03 | 安全 | 密码不得明文存储；登录接口防暴力破解（限流/锁定）；租户数据隔离不可越权；关键操作写 `SystemLog` |
| NFR-04 | 可用性 | 关键单据（采购/销售/库存/资金）需提供列表、详情、打印；表单校验即时反馈 |
| NFR-05 | 兼容性 | 管理端/商户端兼容主流浏览器（Chrome/Edge/Firefox）；移动端适配 uni-app 支持平台 |
| NFR-06 | 可维护性 | 遵循仓库 Java 文档注释规范与前端既有代码风格；新增功能需同步更新本文档与相关说明 |
| NFR-07 | 可扩展性 | 商户/账套维度可扩展；模块授权可扩展（新增菜单即可授权）；预留财务凭证、发票等扩展点 |
| NFR-08 | 数据备份 | 支持定期备份与手动备份（`DataBackup`），备份可恢复 |
